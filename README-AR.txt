إصلاح زر الموظفين والصلاحيات

سبب المشكلة: الأدمن الرئيسي ليس صاحب اشتراك متجر. فتح الزر كان يستدعي دالة إدارة موظفي متجر فتُرجع رفض وصول، ثم كانت الواجهة تخفي النافذة وتبقي مرجعها القديم، فلا تفتح عند الضغط مرة أخرى.

الإصلاح:
- الأدمن الرئيسي يفتح من الزر نافذة توضح دوره وزراً يفتح إدارة الحسابات وتحديد العدد المسموح لكل متجر، دون طلب اشتراك للأدمن.
- صاحب المتجر يفتح نافذة إدارة موظفيه وصلاحياتهم من حسابه.
- أخطاء اتصال صاحب المتجر تبقى ظاهرة بالنافذة، وتبقى قابلة للإغلاق وإعادة الفتح.
- إيقاف صلاحيات الموظف الفعلي يبقى مطبقاً عند التحقق من الخادم.

التثبيت:
ارفع الملفات الأربعة الموجودة بالحزمة إلى جذر مستودع HA-Accounting مع استبدال الملفات السابقة:
index.html
ha-staff.js
ha-app-update.js
service-worker.js

هذا إصلاح واجهة؛ لا يحتاج تشغيل SQL جديد أو تعديل دوال Supabase.
بعد انتهاء نشر GitHub Pages اضغط تحديث البرنامج، أو على الحاسبة Ctrl+Shift+R.

الاستخدام:
1. بالأدمن الرئيسي: الموظفون والصلاحيات > فتح إدارة الحسابات وتحديد العدد. حدد حداً للحساب المطلوب واحفظ.
2. ادخل بحساب صاحب المتجر: الموظفون والصلاحيات > إضافة موظف، وحدد صلاحياته.
3. الموظف يدخل من شاشة الدخول الاعتيادية بمعرّفه وكلمة مروره.

فُحص محلياً فتح الزر للأدمن دون استدعاء اشتراك متجر، وبقاء نافذة رفض الوصول لصاحب المتجر قابلة للفتح والإغلاق، وعدم إبطال جلسته بسبب خطأ إدارة الموظفين، مع فحوص تسجيل الدخول والموظفين والتحديث السابقة. لا تُحذف أو تُعدّل الفواتير والديون أو أرصدة المخزون بهذا الإصلاح.
