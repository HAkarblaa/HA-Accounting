HA Accounting — إضافات المعالجات: عرض سعر + نقطة بيع + المواد المستهلكة
الإصدار 27 — 19/11/2026

وين تظهر؟
كل إضافة إلها مربع مستقل بلوحة المعالجات، واختصار بالشريط السفلي، وزر بالقائمة الجانبية والتنقل الداخلي.
المربعات الجديدة تدخل بنظام تخصيص المربعات الحالي: إخفاء، إرجاع وترتيب. تفضيلات المربعات السابقة تبقى محفوظة.
الشريط السفلي يدعم السحب الأفقي بالموبايل إذا كثرت الاختصارات. تظهر الاختصارات أيضاً عند دخول صفحات المعالجات من الواجهة الكاملة للأدمن.

1) عرض سعر
- إضافة اسم الزبون والتاريخ وصلاحية العرض الاختيارية.
- اختيار المنتجات والكميات وأسعارها، والخصم والضريبة والتوصيل والملاحظات.
- الأسعار في عرض السعر بالدينار العراقي.
- حفظ، تعديل، حذف العرض غير المحول، وطباعة أو PDF بتنسيق الفواتير الحالي وأحجامه.
- العرض لا يخصم مخزوناً ولا يحجز كمية، ولا يسجل بيعاً أو ديناً أو قبضاً.
- تحويل لفاتورة يفتح فاتورة بيع مملوءة بمواد العرض وأسعاره وخصمه وضريبته وتوصيله وملاحظاته، مع تاريخ بيع جديد.
- تراجع الكمية والدفع والزبون قبل حفظ الفاتورة. إذا كان اسم الزبون جديداً، يظهر ضمن إضافة الزبون المباشرة ويُحفظ مع الفاتورة.
- عند الحفظ فقط تُسجل المبيعات والدين أو المقبوضات والمخزون حسب طريقة الدفع.
- يظهر ارتباط العرض بالفاتورة، ويُمنع تحويل العرض مرة ثانية أو تعديله/حذفه بعد التحويل.
- العرض المنتهي يحتاج تعديل صلاحيته قبل تحويله.
- يمكن عرض كمية أكثر من الرصيد في عرض السعر، لكن التحويل لا يحفظ بيعاً فوق الرصيد الفعلي المتاح.

2) نقطة بيع للمعالجات
- شاشة منتجات من مخزون المعالجات فقط، بحث بالاسم، وإضافة سريعة للسلة.
- قراءة باركود بالقارئ الخارجي أو إدخاله يدوياً أو بالكاميرا باستخدام قارئ البرنامج الحالي.
- أضف باركود المنتج من المخزون ← تعديل المنتج. يبقى الباركود نصاً حتى تُحفظ الأصفار في بدايته، ويُمنع تكراره في حقل الباركود لمنتجين.
- تكرار قراءة المنتج يزيد كميته بنفس السطر، ضمن الرصيد المتاح.
- تعديل كمية وسعر، حذف سطر، أو تفريغ السلة.
- متابعة الدفع تفتح فاتورة البيع المعتادة بمواد السلة: نقد، آجل، أقساط، صندوق أو مصرف، خصم وضريبة وتوصيل وملاحظات وإضافة زبون.
- لا يتغير المخزون أثناء إضافة السلة، وإنما بعد حفظ الفاتورة مرة واحدة.
- بعد نجاح الحفظ تتفرغ السلة وتظهر طباعة/PDF لآخر فاتورة. عند فشل الحفظ تبقى قابلة للتصحيح وإعادة المحاولة.
- السلة مسودة بالذاكرة: تبقى أثناء التنقل بين الصفحات، ولا تُحفظ بعد إغلاق البرنامج أو إعادة تحميله. الفاتورة المحفوظة تبقى ضمن المبيعات.

3) المواد المستهلكة
- تسجيل منتج وكمية استخدام داخلي وملاحظات، بتاريخ اليوم.
- تنقص كمية المخزون، وتُحسب كلفة الاستهلاك من أقدم دفعات المخزون الفعلية (FIFO)، وليس بسعر البيع.
- تدخل الكلفة ضمن مصروف إخراج المخزون وصافي الربح مرة واحدة، بدون إنشاء سند نقدي أو تغيير ديون الزبائن والمجهزين.
- كشف مستقل حسب الفترة والمنتج: رقم الحركة، التاريخ، الكمية، الكلفة الفعلية والملاحظات، مع طباعة وPDF.
- تعديل حركة الاستهلاك متاح، مع منع تعديل حركة لها حركات مخزنية أحدث حتى لا تختل كلفة الدفعات.
- سجل التالف والمنتهي يبقى منفصلاً عن سجل الاستهلاك. التقرير المالي العام يعرض إخراج المخزون مع السبب الصحيح لكل حركة.

التثبيت
1. فك الضغط وارفع ملفات البرنامج الموجودة بجذر الحزمة إلى جذر مستودع HA-Accounting، مع استبدال الملفات المطابقة.
2. ارفعها بنفس Commit حتى تتطابق نسخة الواجهة وخدمة التحديث.
3. بعد اكتمال نشر GitHub Pages، افتح البرنامج وحدّثه. إن لم يظهر الإصدار الجديد، استخدم زر تحديث البرنامج الموجود.
ملفا README-AR.txt وSHA256SUMS.txt للشرح والتحقق فقط، ولا تحتاج رفعهما للموقع.
هذه الحزمة تراكمية وتحتفظ بتعديلات المرتجعات والكشوف والطباعة والكامرة والتحديث السابقة. لا تحتاج رفع الحزمة السابقة أولاً إذا كان المشروع الأساسي موجوداً.
لا تحتاج SQL أو دالة Supabase جديدة لهذه الإضافات. لا تبدّل supabase-config.js؛ ليس موجوداً بالحزمة.
لا تمسح بيانات التطبيق ولا تحذفه. الإضافة لا تحذف الفواتير أو بيانات الحساب الحالية.
الحزمة جاهزة للرفع؛ لم تُنشر على موقعك مباشرة.

التحقق
نجحت فحوصات حفظ عرض السعر بدون أثر مالي، حساب المجاميع، التحويل مرة واحدة، منع الكميات الزائدة والعروض المنتهية أو المعدلة، فشل الحفظ وإعادة المحاولة، مبيعات الباركود، السلة، الحفظ النقدي، FIFO للاستهلاك وكلفته وعدم إنشاء دفعة نقدية، طباعة العروض وكشف الاستهلاك، ظهور المربعات مع تفضيلات التخصيص السابقة، وتشغيل الاختصارات الفعلية لصاحب الحساب والأدمن الكامل.
جُرّبت التحديثات المتزامنة للتأكد من قراءة أحدث دفتر معالجات قبل تحويل عرض محفوظ.
نجحت أيضاً اختبارات الانحدار للفواتير والمرتجعات والطباعة والتحديث وحدود الشاشة وقارئ الكاميرا الحالي. الاختبارات برمجية وDOM؛ لم يجر اختبار ميداني على هاتف أو طابعة فعلية ضمن هذه المهمة.
